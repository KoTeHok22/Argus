# Алгоритм

## Идея

Мы не классифицируем объекты. Мы описываем **нормальный тоннель** и ищем всё, что в него
не вписывается внутри габарита движения поезда. Это map-based anomaly detection,
на который прямо указывает ТЗ («нужно научиться хорошо описывать нормальный тоннель, а
затем искать всё, что в него не вписывается»).

Формально на каждом кадре:

```
Есть ли в габарите точки, которые не согласуются с нормальной геометрией тоннеля?
```

Три независимых признака аномалии:

1. **Геометрический residual** — точка оказалась ближе, чем предсказывает профиль
   окружения (стены) на этом азимуте.
2. **Нет возврата** — луч в прямом секторе, который раньше давал стену, пропал
   (что-то поглотило сигнал).
3. **Free-space violation** (опционально) — точка в ранее свободном пространстве карты.

## Шаг 1. Очистка облака

`argus_core/cloud_filter.cpp`. Раскладка полей читается из сообщения (`parse_layout`).
Отбраковка (первой, до всего остального):

```
isfinite(x,y,z) ∧ 0.5 < √(x²+y²+z²) < 400 ∧ |coord| < 10⁴
```

Нулевые `(0,0,0)` отбрасываются и одновременно помечаются как «нет возврата» —
это вход для no-return детектора. Отбрасывается 50–75 % точек кадра.

## Шаг 2. Range image

`argus_core/range_image.cpp`. Из `raw_idx` точки восстанавливается ячейка:

```
ring = raw_idx mod H
az   = raw_idx div H
range[az][ring] = √(x²+y²+z²)
```

Для Hesai Pandar128: `H = 128`, `az ∈ [0, 2400)`. Это развёртка `azimuth × ring`,
построение за O(N) без KD-tree. Соседство по ячейке = физическое соседство по углу.

## Шаг 3. Вычитание пола и рельсов

`argus_core/ground.cpp`. Метод по умолчанию — `z_threshold`: точки ниже
`sensor_height − max_ground_z_rel` считаются полом и удаляются. В зоне рельсов
(`rail_zone_m`) действует отдельный порог `rail_max_height`. Patchwork++ доступен как
опция (`method: patchworkpp`). Пороги по Z работают в колее и дают 153→136 мс против
Patchwork++ на тех же данных.

## Шаг 4. Геометрический residual — ядро

`argus_core/anomaly_geometry.cpp`. Для каждой ячейки range image строится **базовый
профиль** — скользящая медиана дальности по азимуту в окне `median_half_window`:

```
baseline[az][ring] = median( range[az−k … az+k][ring] ),  k = median_half_window
```

- `median_half_window = 100` (production).
- Отдельное окно `200` применяется только к возвратам 18.5–40 м
  (`median_half_window_override`) — чтобы видеть широкие цели на 20 м, не ломая
  обнаружение известного препятствия на 16.9 м.

Residual — насколько точка ближе базового профиля:

```
residual = baseline − range
аномалия, если residual > residual_threshold_m (1.0 м)
```

Порог мягче для дальних возвратов (`residual_threshold_far_m`), что расширяет конверт
до 150 м. Ячейки-аномалии собираются в 8-связные компоненты на развёртке, к компоненте
применяются гейты: `min_cells` (50 ближних / 8 дальних от 60 м),
`min_fill` (0.30 / 0.12). Азимутальный центр считается взвешенно по `1/range²`.
Кандидат должен повториться в `min_stable_frames` кадрах подряд (`az_tolerance`,
`range_tolerance_m`).

## Шаг 5. Нет возврата

`argus_core/anomaly_no_return.cpp`. На кольце ищутся непрерывные серии «нет возврата»
длиной `min_missing_run` (8) и не длиннее `max_missing_run_deg` (15°). Серия считается
аномалией, если по её краям в окне `azimuth_window` достаточно живых возвратов
(`min_baseline_hits` 0.70) и медиана их дальности ≥ `min_range`. Признак ловит объекты,
поглотившие луч, без всякой геометрии.

## Шаг 6. Временной residual (опция)

`argus_core/anomaly_temporal.cpp`. Текущий range image сравнивается с медианой пяти
предыдущих кадров; residual > 0.5 м — аномалия. История сбрасывается при разрыве
штампов > `max_frame_gap_s` (0.5 с). Наивная версия без компенсации движения даёт
ложные срабатывания на поворотах, поэтому по умолчанию выключена
(`fusion.use_temporal_candidates: false`).

## Шаг 7. Free-space violation (опция)

`argus_core/anomaly_free_space.cpp`. `TunnelModel` строит воксельную карту: воксель
свободен, если луч прошёл сквозь него `free_hits_to_clear` раз, занят при
`min_observations` попаданиях. Точка внутри подтверждённо свободного вокселя — аномалия.
В production выключено: на платформе давало 47/300 против 21/300 без него.

## Шаг 8. Кластеризация

`argus_core/clustering.cpp`. Аномальные точки собираются в кластеры с адаптивным
радиусом соседства (`neighbor_distance` 0.35 м, растёт с дальностью). Минимальный
размер кластера — лесенка по дальности: 15 (≤60 м) → 6 (≤120 м) → 3 (≤200 м) → 2 (≤300 м),
чтобы разреженная дальняя цель не отбрасывалась. Гейты `min_extent_m` (0.20) и
`max_extent_m` (5.00). Кластеру считаются центроид, объём, ближайшая дальность,
`forward_distance` и голоса источников (`votes_geometry/no_return/free_space/temporal`).

## Шаг 9. Трекинг

`argus_core/tracking.cpp`. Кластеры ассоциируются с треками по расстоянию
(`max_association_distance` 2.0 м). Подтверждение адаптивно по дальности:
3 кадра ближе 60 м, 5 кадров дальше 120 м (интерполяция между). Трек хранится при
`max_misses_to_keep = 4`. Считаются скорость сближения и TTC.

## Шаг 10. Габарит и решение

`argus_core/gauge.cpp` (`ClearanceGauge`) — параметрический габарит поезда: полуширина
1.50 м, высота 2.10 м над головкой рельса, `base_offset` 0.20, фаска 0.20,
`sensor_height` 1.075 м. Ось «вперёд» — `−Y`. `contains_at_path` проверяет точку в
координатах пути (важно на повороте, где мировая координата Y ≠ расстояние вдоль рельсов).

`FusionPipeline::update` (`argus_core/fusion.cpp`) оставляет подтверждённые треки внутри
габарита и с достаточной свежестью: дальний трек (90 м+) после более 4 пропусков
перестаёт тревожить. Результат — ближайшая дальность и статус.

`argus_core/supervision.cpp` — надзор скорости: `braking_distance_m = v·t_реакции +
v²/(2a) + запас`; `forward_visibility_m` — как далеко вперёд реально виден свободный путь;
`speed_limit_mps` — скорость, при которой тормозного пути хватает до границы видимости.

## Верификатор кластера (опция, выключен в production)

`argus_core/verifier.cpp` (`ClusterVerifier`) — объяснимый скоринг кластера по
классическим признакам: плотность точек относительно размера и дальности, residual-score,
«плитообразность» (тонкий широкий слой — стена), минимальный собственный размер, число
точек. Каждый вердикт имеет `reason`. Верификатор выключен по умолчанию; A/B показал, что
пороговых признаков недостаточно, чтобы отделить фоновую структуру от реального
препятствия (см. `docs/EXPERIMENTS.md` T100). Это честный отрицательный результат, и
именно поэтому он не включён в конвейер.

## Классификация (объяснимая, без нейросети)

`argus_core/classification.cpp` присваивает треку `unknown/person/debris/equipment` и
строку `class_reason` по extent и числу точек. При вырожденном вертикальном extent
(< 5 см) отдаётся `unknown/no_height_evidence` — система не выдумывает класс без улик.

## Два режима дальности

- **Тоннель узкий/кривой:** дальность ограничена стеной (профиль уходит на 20–30 м),
  обнаружение на 300 м физически невозможно — стена закрывает обзор.
- **Тоннель прямой:** профиль уходит на сотни метров, там дальность имеет смысл.

Это различие важно для интерпретации результата: «не увидел на 300 м» в узком тоннеле
не означает пропуск.

## Ограничения метода

- Детектор не видит то, что закрыто ближней поверхностью (медианный baseline по тем же
  лучам может погасить широкую близкую цель).
- Порог по Z для земли прост, но на сложной геометрии полотна уступает адаптивным
  методам; Patchwork++ доступен как опция.
- Мировой анализ зависит от одометрии; при плохой позе world-space признаки отключаются.
- Recall на 60–100 м подтверждён только на синтетических целях; на реальных данных
  устойчивый конверт скромнее (см. `docs/EXPERIMENTS.md`).
