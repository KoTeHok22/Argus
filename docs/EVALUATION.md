# Оценка по размеченным объектам

Оценщик считает полноту по объектам и кадрам, первую дальность обнаружения и события
ложных треков. Потерянные кадры и малое число лучей не исключают размеченную цель из
знаменателя. Инструмент готов; независимого размеченного набора в репозитории пока нет.
Результаты тестовых фикстур не являются результатами качества Argus.

## Подготовка

Разделить исходные записи по группам поездок до настройки. Фрагменты одной записи
должны иметь общий `group_id`. Уже использованные записи относятся к `development`,
даже если раньше назывались holdout. Новый holdout нельзя использовать для выбора
порогов или исправления детектора с последующей оценкой на нём же.

Разметить полную временную шкалу источника, включая все опасные цели в габарите.
`reviewed: true` означает проверку всех целей кадра; пустой список означает проверенное
отсутствие целей. Для непроверенного кадра ставить `reviewed: false` и пустой список.
Частичная разметка даёт метрики только на проверенных кадрах. Стабильный `object_id`
обозначает одну физическую цель в пределах сцены. Размеры, классы и попадание в габарит
должны соответствовать ТЗ и проверяться при подготовке разметки.

Центры задаются в метрах в исходной системе LiDAR данного кадра. Допуск сопоставления
фиксируется до прогона. Пример 1 м / 150 мс ниже иллюстрирует формат, а не стандарт ТЗ.

## Команды и форматы

Из корня checkout:

```text
python argus_eval/argus_eval/benchmark.py freeze evaluation/spec.json evaluation/manifest.json
python argus_eval/argus_eval/benchmark.py score evaluation/manifest.json evaluation/predictions.json evaluation/report.json
```

Пути спецификации считаются относительно её каталога. `freeze` закрепляет полный
Git-коммит детектора, команду запуска, конфигурацию, исходные записи и разметку.
SHA-256 вычисляется по полным файлам; изменение байтов делает старый прогон
недействительным. Выходные файлы не перезаписываются.
Manifest хранит пути относительно своего каталога, поэтому комплект можно перенести
с сохранением структуры. Для файлов на другом диске Windows путь остаётся абсолютным;
для переносимого комплекта сначала собрать файлы в одной структуре каталогов.

Пример `spec.json` — подставить реальный коммит и команду запуска:

```json
{
  "detector_revision": "183565e0515f645391ea4140a60c148cb53c9319",
  "run_command": "actual detector invocation with all arguments",
  "detector_config": "params.yaml",
  "protocol": {"max_center_error_m": 1.0, "max_event_gap_ns": 150000000},
  "scenes": [{
    "scene_id": "new-trip", "group_id": "new-recording",
    "split": "holdout", "unseen_at_freeze": true,
    "source": "new-trip.frames", "annotations": "new-trip.labels.json"
  }]
}
```

Файл разметки:

```json
{
  "source_sha256": "SHA-256 of the complete source file",
  "coordinate_frame": "lidar", "synthetic": false,
  "reference_distance_verified": false,
  "frames": [{
    "stamp_ns": 100000000, "reviewed": true,
    "objects": [{"object_id": "person-1", "position_m": [0, -20, 0.5]}]
  }]
}
```

Опорный путь необязателен. Если он проверен независимо, поставить
`reference_distance_verified: true` и добавить накопленный `path_m` в каждый кадр.
Путь должен быть неубывающим. Путь по назначенной вручную скорости или непроверенной
ICP-одометрии нельзя объявлять проверенной опорной дистанцией.

После запуска сохранить `predictions.json`:

```json
{
  "manifest_sha256": "SHA-256 of manifest.json",
  "detector_revision": "183565e0515f645391ea4140a60c148cb53c9319",
  "detector_config_sha256": "value from manifest.json",
  "scenes": {"new-trip": {
    "source_sha256": "value from manifest.json",
    "frames": [{
      "stamp_ns": 100000000,
      "detections": [{"track_id": "17", "position_m": [0, -20.2, 0.5]}]
    }]
  }}
}
```

`detections` содержит только подтверждённые объекты, не кандидатов. При адаптации
`detect_watch.py` использовать `stamp_ns` и позиции из `obstacles_json`. Его
`source_frame` — счётчик полученных сообщений; при потерях это не номер исходного
кадра. CSV с одной `nearest_m` недостаточно для оценки объектов. Пустое предсказание —
полученный кадр без обнаружений; отсутствующий кадр — потеря сообщения. Временные
метки строго возрастают и совпадают с источником.
Идентификаторы строковые; числовой `track_id` из ROS нужно преобразовать в строку.

## Отчёт

| Поле | Значение |
|---|---|
| `object_recall` | Доля уникальных целей, найденных хотя бы один раз |
| `object_frame_recall` | Доля присутствий целей в кадрах с совпадением |
| `first_detection_range_m` | Дальность размеченного центра при первом по времени совпадении |
| `prediction_coverage` | Доля исходной размеченной временной шкалы с предсказанием |
| `annotation_coverage` | Доля кадров с полной проверенной разметкой |
| `false_detections` | Число несопоставленных подтверждённых обнаружений |
| `false_track_events` | Серии несопоставленных обнаружений одного `track_id` |
| `false_track_events_per_km` | События на проверенный путь; иначе `null` |

Сопоставление один к одному максимизирует число геометрически допустимых совпадений.
Дубликат не повышает полноту и остаётся ложным обнаружением. Событие разрывается сменой
трека, кадром без этого ложного трека, потерянным или непроверенным кадром либо
превышением интервала протокола. Сбросы идентификаторов увеличивают число событий;
это метрика ложных **треков**, а не команд торможения.

`null` у recall означает отсутствие размеченных целей, а не 100% успеха. Без
положительного проверенного пути событий/км нет. Результаты сцен сохраняются отдельно;
среднее процентов сцен нельзя выдавать за полноту всего набора.

`declared_unseen_real_holdout` — заявление оператора о новой реальной записи с полной
разметкой. Хэши подтверждают неизменность файлов и совпадение квитанций, но не
правдивость разметки, полноту исходной временной шкалы, независимость данных или запуск
указанного бинарника. Ревьюер проверяет это по журналу поездок, разметке и запуску.
`freeze` сам не запускает детектор. Все дополнительные настройки и конфиги нужно
включить в единый конфигурационный файл и сохранить фактическую команду запуска.
