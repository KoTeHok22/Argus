# Argus

Система обнаружения посторонних объектов в габарите подвижного состава по данным
3D-лидара. На каждом кадре отвечает, есть ли препятствие впереди и на каком расстоянии.

Это не нейросеть и не общий детектор объектов. Система описывает **нормальную геометрию
окружения** и ищет всё, что в неё не вписывается внутри габарита движения. Работает
на CPU, GPU не нужен.

## Быстрый старт: от нуля до результата

```bash
git clone <repo> && cd Argus
./scripts/fetch_third_party.sh
docker build -f docker/Dockerfile -t argus .
docker run --rm --shm-size=256m \
    -v "$PWD/data/recordings":/data \
    argus detect /data/<recording> 1
```

`<recording>` — каталог записи rosbag2 (`metadata.yaml` и `*.db3`). Через несколько секунд
система печатает решения по кадрам. На записи с препятствием ожидаются строки такого вида:

```
ALERT BLOCKED objects=2 nearest=16.9m fps=10.0 fusion=0.9ms path=100.6ms
CLEAR objects=0 nearest=-1.0m
```

На свободном участке тревог нет: `CLEAR`. Для коротких записей используйте `--rate 0.5`
(аргумент после пути): на общем CPU контейнера 10 Гц из сотен тысяч точек может не
укладываться, и часть кадров теряется в очередях.

Плеер чтения записи свой (`docker/bag_play.py` на `rosbag2_py`), а не `ros2 bag play`:
CLI в целевом образе открывает базу, но не публикует сообщения из-за мисматча плагинов
хранилища. Вернуть CLI можно переменной `ARGUS_PLAYER=cli`.

## Проверено живым E2E

| Сценарий | Результат |
|---|---|
| Препятствие, `detect … 0.5` | 9 × `ALERT BLOCKED`, ближайшее **16.9 м** |
| Свободный участок | 111 кадров, **0 тревог** |
| Поворот | 60 кадров, **0 тревог** |
| Held-out запись (7 ГБ) | без сбоев, **0 тревог** |
| Отказ узла (`scripts/fault_injection_test.sh`) | `OK → DEAD:<узел> → STATUS_DEGRADED` |
| `ros2 launch … bag:=` (demo-путь) | `/argus/obstacles` = `CLEAR` на пустой записи |

Панель в браузере (`http://localhost:8080`): загрузка записи, эфир облака, отчёт.

```bash
docker run --rm --shm-size=256m -p 8080:8080 \
    -v "$PWD/data/recordings":/data -v "$PWD/results":/ws/results argus ui
```

Без Docker панель: `./scripts/run_ui.sh`, в Windows — `$env:PYTHONPATH="argus_web"; python -m argus_web`.

`--shm-size=256m` обязателен: один кадр занимает десятки мегабайт.

## Что проверено

Числа получены на закрытых записях заказчика и воспроизводятся офлайн-прогоном; разметки
по кадрам нет, поэтому они приведены как инженерные ориентиры, а не как точный recall.

| Проверка | Результат |
|---|---|
| Запись с контролируемым препятствием | срабатывание с 3-го кадра, объект на ~17 м |
| Запись без препятствий | нет ложных срабатываний на длинном участке |
| Второй набор сцен | единичные тревоги, устойчивые регрессии сохранены |
| p95 пути принятия решения | ~30 мс (бюджет 100 мс) |
| Тесты | 249 тестов, 0 ошибок |

Километровая нормировка (`scripts/eval/metrics_report.py`) — приближённая, без покадровой
разметки.

## Чего система не делает (ограничения)

- **Дальность.** Устойчивое обнаружение малого объекта на реальных данных — десятки
  метров. На синтетических целях размера габарита сигнал есть дальше, но это не
  подтверждает реальный recall. В узком или кривом участке стена физически закрывает
  обзор, и большая дальность там недостижима.
- **Реклассификация.** Класс объекта (`person`/`debris`/`equipment`) — грубая эвристика
  по размеру, не обученная модель; на вырожденных целях отдаётся `unknown`.
- **Свободное пространство и временной канал** в production выключены: давали ложные
  тревоги на платформе и поворотах.
- **Одометрия** в замкнутом пространстве деградирует продольно; признаки в мировой
  системе используются только при подтверждённом качестве позы.
- **Ложная тревога на статичном артефакте.** На стоящем составе статичный край пути и
  настоящее препятствие геометрически неразличимы: нет движения и параллакса. Это
  устраняется только памятью места или обученной моделью.
- Система **не даёт команду торможения**. Вместо «путь свободен» система честно различает
  состояния отказа: `DEGRADED` — отказ инфраструктуры (нет кадра/позы, неисправен сенсор,
  молчит узел); `UNKNOWN` — проверенной дальности свободного пути меньше порога, улик на
  достоверный `CLEAR` не хватает; `BLOCKED`/`WARNING` — подтверждённое препятствие.
  `CLEAR` выдаётся только когда система действительно видит достаточно.

## Как работает (кратко)

1. Читает облако точек по фактической раскладке `fields[]` (не по зашитым offsets).
2. Отбрасывает мусор (большую часть точек кадра) и помечает лучи без возврата.
3. Вычитает пол и рельсы порогом по Z (Patchwork++ — опция).
4. Строит range image (2D-развёртку азимут × кольцо).
5. Геометрический residual: точка ближе скользящей медианы профиля на азимуте → аномалия.
6. Подтверждает аномалии во времени и проверяет принадлежность габариту.

Подробно: [`docs/ALGORITHM.md`](docs/ALGORITHM.md).

## Режимы контейнера

| Команда | Назначение |
|---|---|
| `detect <recording> [rate] [params]` | Прогон записи с выводом результата |
| `demo <recording>` | Прогон с визуализацией RViz2 |
| `eval <recording>` | Отчёт по прогону |
| `ui` | Панель в браузере |
| `shell` | Оболочка внутри образа |
| `help` | Справка (по умолчанию) |

## Проверки

```bash
scripts/ci/all.sh                    # lint + build + test
scripts/fault_injection_test.sh      # fail-safe: kill узла → DEGRADED
scripts/eval/frozen_report.sh        # единый отчёт по наборам
scripts/eval/metrics_report.py <csv> # события/км и FP/км
```
